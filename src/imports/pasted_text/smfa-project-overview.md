Figma Make Prompt – SMFA School Management Platform (MVP) Project Overview Design a responsive web application for a school operations platform (SMFA) that serves five primary user roles: Admin, Principal, Teacher, Bursar/Accountant, Parent/Guardian, plus supporting roles (Gate Staff, School Nurse). The platform manages syllabus creation, lesson notes with AI generation, practice questions, fee receipts and reconciliation, result gating, performance analytics, parent–staff notes, pickup/departure codes, student medical records, and medication scheduling. Design Direction: Modern, clean, professional, and approachable (education‑focused). Mobile‑first responsive – parents and teachers will use phones heavily. Card‑based UI with plenty of white space, subtle shadows, and rounded corners. Support both light and dark mode (optional but preferred). Use a neutral color palette with an accent color (e.g., blue or green for primary actions). Icons should be clear and consistent (Feather or Material style). Real‑time notification badges, approval queues, and status indicators. User Roles & Dashboards 1. Parent / Guardian Dashboard Purpose: One‑stop view for a parent managing one or more children. Key components: Child selector (top bar) – switch between children. Overview cards: Upcoming medication reminders (if any) Pending fee receipts Active pickup codes Unread notes from staff Quick actions: “Generate practice questions” (opens modal with subject/difficulty) “Upload fee receipt” “Generate pickup code” “Send note to teacher” Performance section: Line chart showing term‑over‑term average trend Subject breakdown table (subject, score, class average, position) “View full report card” button (gated by fees + release) Medical & medication section: Summary of allergies / conditions List of active medications with “fulfillment history” link Transport preference: Dropdown to set/change preference (self, parent, authorized, school bus) Recent activity feed: Notifications (medication given, note received, receipt approved, etc.) 2. Teacher Dashboard Purpose: Manage syllabus, lesson notes, questions, and student updates. Key components: Top bar: School/class selector, notification bell, profile. Syllabus panel: List of weeks for selected class/subject/term Status badges (draft, submitted, approved, rejected) Buttons: “Create new week”, “Submit for approval” (for draft/rejected), “Edit” “Generate from master syllabus” option Lesson notes panel: For each approved syllabus week, a “Generate lesson note” button List of existing lesson notes with status and AI metadata “Submit for approval”, “Edit draft” Question bank: Table of manual questions (filter by subject, difficulty) “Create manual question” form “Generate questions with AI” (select source: syllabus/lesson note) Student performance: Quick view of class average per subject Link to class analytics Quarterly updates: List of students in class, each with “Add quarterly update” button Form with fields: academic progress, strengths, areas for improvement, behavior notes, recommendation Medication reminders panel: “Medications due now” list with “Mark as given” button 3. Principal Dashboard Purpose: Oversee approvals, release results, and view school‑wide analytics. Key components: Approval queues (two tabs): “Pending Syllabus Approvals” (card list, each with expandable details, Approve/Reject buttons + reason field) “Pending Lesson Note Approvals” (similar) Result release control: Card per term with toggle “Release results” and timestamp of last change Warning if fees are incomplete for any student School analytics: KPI cards: overall pass rate, average score, top/bottom performing classes Bar chart of subject averages Table of class performance (class, average, rank) Teacher performance (list of teachers with average score of their students) Fee dashboard (read‑only): Pending payments count, approval rate, aging summary Departure logs export button Medical overview (privacy‑restricted): Count of students with active medications, allergies, etc. (no individual names) 4. Bursar / Accountant Dashboard Purpose: Process payment receipts and reconcile fees. Key components: Pending payments queue: Table with columns: student name, amount declared, account number, payment date, receipt thumbnail Action buttons: “Approve”, “Reject” (opens modal for comment) Filter by date range, search by student name Approval metrics: Average approval time, total approved/rejected this week “Mismatch alerts” list (where AI‑extracted amount differs from declared) Fee item management (admin also has this): List of fee items per term (tuition, lab fee, etc.) with CRUD buttons 5. Admin Dashboard Purpose: System configuration and user management. Key components: School setup: Manage classes (CRUD) Manage subjects (use master list + add custom) Manage terms (start/end dates, active flag) Feature flags toggles (AI generation, require principal approval, result gating) User management: List of staff, parents, students with role assignment Invite new users (email) Audit logs viewer: Filterable table of all critical actions (syllabus approvals, fee decisions, result toggles) AI usage report: Quota used per school, per role, with reset option 6. Gate Staff / Security Dashboard (simple) Purpose: Verify pickup codes and log departures. Key components: Pickup code verification input: Large text field + “Verify” button After verification: show child name, authorized by, button to “Confirm departure” Today’s departure log: List of children already picked up (with time and verifier) 7. School Nurse Dashboard Purpose: Manage medical records and medication fulfillment. Key components: Search student (by name/class) → view/edit medical record and medications Medications due today: List grouped by time, each with “Mark given” button Option to mark as “missed” or “deferred” with note Fulfillment history per student Common Components (Reusable) Sidebar navigation – collapsible, with role‑specific menu items. Top bar – school name, user avatar + role, notification bell (with unread count). Status badges – draft (gray), submitted (yellow), approved (green), rejected (red). Approval modal – for principal/bursar: shows content, has “Approve” / “Reject” with reason field. Form modals – for creating syllabus, lesson note, manual question, fee item, medication, etc. Data tables – sortable, filterable, with pagination. Charts – line (trends), bar (comparisons), donut (pass rate). Notification toast – real‑time alerts for medication reminders, approval updates, fee status changes. Mobile bottom navigation – for parents and teachers on phone (replaces sidebar). Key User Flows (to be designed as clickable prototypes) Parent generates practice questions Chooses child → selects subject/difficulty → clicks “Generate” → sees questions with answers. Teacher creates syllabus and submits for approval Selects class/subject/term → fills week form → saves as draft → submits → principal receives notification. Principal approves syllabus Opens pending queue → expands item → reads content → clicks approve (or reject with reason). Parent uploads fee receipt Clicks “Upload receipt” → fills amount, account details, payment date → allocates to fee items → submits → sees pending status. Bursar approves receipt Opens pending queue → clicks “View receipt” → approves with comment → parent receives notification. Parent views report card Clicks “View report card” → if fees incomplete or results not released, sees clear error message; else sees full report card with download PDF option. Teacher marks medication as given Sees reminder in dashboard → clicks “Mark given” → selects student (pre‑filled) → submits → parent gets notification. Parent generates pickup code Selects child → clicks “Generate pickup code” → sees code and expiry → shares with authorized person. Gate staff verifies code Types code → system shows child name → clicks “Log departure” → code invalidated. Design Assets & Deliverables for Figma Make High‑fidelity mockups for all dashboards (desktop 1440×900 and mobile 390×844). Interactive components (dropdowns, modals, tabs, toggles). Design system – color palette, typography (sans‑serif like Inter), spacing scale, button states. Icon set – consistent outline style. Prototype linking – connect major flows (e.g., pending queue → approval modal). Dark mode variant (optional but nice). Additional Notes for Figma Make Use realistic dummy data (student names, subjects, dates) to make the design tangible. Show error states (e.g., result gating message, form validation). Include loading skeletons for tables/charts. Ensure accessibility (high contrast, focus indicators, proper labels).
